# Storyboard «ИИ в работе» — визуальный и анимационный язык

## Глобальные принципы

- Один постоянный canvas (`MasterclassCanvas`) со сменой состояний; текст — всегда HTML.
- Pinned-сцены (8): program-vs-ai, generation, chat-assistant-agent, four-p, cycle, ladder, enterprise-why, enterprise-gateway. Между ними — спокойные секции.
- Каждая анимация отвечает на вопрос «что изменилось / кто контролирует / как связано».
- Цвета шагов: Понять `#25C7E8` · Поручить `#E9B24B` · Проверить `#42C98A` · Перестроить `#8D6BFF`.
- Motion tokens: см. `src/components/masterclass/motion.ts` (instant 0.12 … cinematic 1.2; scrubSoft 0.7).
- Easing: power2.out (UI), power3.out (крупные смыслы), power2.inOut (переходы состояний), expo.out (редкие акценты).
- Reduced-motion / mobile / нет WebGL: canvas выключен, статичные композиции, контент полный.

## Сцены (сжатая раскадровка)

### 1. Hero
Тёмный градиент → процедурная сеть точек (три.js): точки поднимаются, линии связываются, редкие импульсы.
Тайтл входит с 12px сдвигом; 4 слова методики подсвечиваются по очереди своими цветами.
При скролле сеть слегка расходится к четырём направлениям (позиционный морф), камера — микро-dolly.

### 2. Why
DOM: строки «сделай текст», «что-нибудь проанализируй» тускнеют → 3 карточки (проблема/цель/результат) → SVG-маршрут из 6 точек, раскрытие по одной (stagger base).

### 3. Program-vs-AI (pin, ~2.5 экрана скролла)
Слева машина правил: вход-квадрат едет по фиксированной дорожке → одинаковый выход (повтор 2 раза).
Scrub-переход: камера/фокус вправо, поле из ~300 узлов; примеры (мелкие точки) вливаются, связи меняют толщину; новый запрос проходит по «размытому» пути → несколько вариантов исхода с разной яркостью.
Финальная плашка: «убедительно ≠ правильно». Подпись «упрощённая визуальная метафора».

### 4. Generation (pin)
Фраза-запрос разбивается на 5–7 смысловых блоков (DOM), блоки летят в «контекстное окно» (SVG-рамка);
переключатель контекста меняет число доступных блоков и полноту условного ответа; ответ печатается построчно; поверх — слой проверки человеком (метки: факт, дата, источник, риск).

### 5. Chat → Assistant → Agent
Один объект-ядро (3D или SVG на mobile): 
чат — одиночная нить диалога; помощник — присоединяются документы и инструкции; агент — цель, план (3 узла), инструменты, рамка границ + точки подтверждения. После третьей стадии — главная фраза.

### 6. Four-P (pin)
Кольцо из 4 секторов собирается; активный сектор выходит вперёд с 2–3 словами; после полного круга кольцо стабилизируется и уменьшается в постоянный навигационный элемент (верхняя панель).

### 7–8. Prompt builder / Good-bad
Каркас из 8 слотов; клик по слоту — объяснение, пример, ошибка, своё поле; «Собрать запрос» — текст.
Плохой запрос: вокруг фразы всплывают знаки вопроса (муар); «Улучшить» добавляет по одному элементу, туман рассеивается (маска).

### 9. Verification cycle (pin)
Кольцо 7 этапов; scrub подсвечивает по очереди; «оценка→уточнение» делает два коротких оборота (стрелка-дуга); финал — маркеры проверки на документе.

### 10. Risk zones
Три горизонтальные полосы допуска (зелёная/жёлтая/красная) с нарастающей плотностью «ограждения»; классификатор задач — карточка → выбор зоны → объяснение (без оценок).

### 11. Maturity ladder (pin)
6 ступеней вверх; на каждой — один и тот же процесс (мини-схема из блоков): ручных блоков меньше, контрольных точек больше; наверху агент в рамке + человек рядом. Затем DOM-слои: критерии и метрики.

### 12–14. Демонстрации
Хаб-схемы SVG: поток текста → 4 колонки; документ-хаб → 6 лучей по очереди; маршрут агента с чек-пойнтами и переключателем контроля (без контроля — красный риск-путь).

### 15. Use cases
Карта из 4 контуров; фильтр роли переставляет акценты и примеры.

### 16. Security (pin)
Концентрические контуры данных; критический слой физически вне канала; агент — внутри малого контура с журналом и кнопкой «стоп».

### 20. Finale
Элементы прежних сцен (сеть, кольцо 4П, ступени, контуры) собираются в одну спокойную композицию вокруг фигуры человека; 5 шагов; карточка пилота. Сеть hero возвращается — история замыкается.

## Бонусный блок: корпоративный ИИ-контур (сцены 17–19)

Позиция: после «Безопасного агента», перед «Карточкой пилота». Тон — управляемость, не страх.
Без клише кибербезопасности (замки, капюшоны, бинарный код). Формулировки без гарантий
(«полностью безопасно» и т.п. запрещены): безопасность = контур + правила + фильтрация + журнал + человек.

### 17. Enterprise-why (pin)
Малый контур агента из предыдущей сцены расширяется до контура предприятия.
Слева — рабочее место и материалы (документ, таблица, договор, переписка, тех.данные, отчёт);
справа — внешнее облако моделей. Потоки: часть проходит, часть останавливается, часть требует
обезличивания, часть остаётся внутри. Три мысли по очереди → «Не запретить ИИ, а сделать его управляемым».

### 18. Enterprise-gateway (pin, центральная)
Схема собирается за 5 этапов скролла: окно сотрудника → корпоративный ИИ-шлюз (правила доступа,
классификация, фильтрация, журналирование, контроль действий) → локальный контур (модель,
база знаний, RAG, внутренние системы) → контролируемый выход наружу (решить локально /
обезличить и направить / остановить / запросить подтверждение) → человек в контуре.
Финал: собранная вертикальная схема + фраза о контроле данных + дисклеймер о концептуальности.
После сборки — учебный маршрутизатор: 5 готовых запросов → подсвеченный маршрут.

### 19. Enterprise-path
«Начинать не с сервера, а с задач»: маршрут из 6 шагов (задачи → данные → пилотный контур →
правила → эффект → масштабирование), три уровня внедрения (пилот → помощник → контур),
связка с 4П и переходная фраза «Любой корпоративный контур начинается с одной правильно
выбранной задачи» → карточка пилота.
