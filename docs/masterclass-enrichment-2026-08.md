# Обогащение мастер-класса — август 2026

Документ фиксирует второй заход по содержанию `/ai-masterclass`: что уже реализовано, какие смысловые
пробелы найдены при повторном разборе управленческого материала, и какие решения приняты по каждой сцене.

Источник идей — внутренний аналитический конспект корпоративного курса по применению ИИ
(`course_AI_selecte;.txt` в рабочей папке автора). Используется **только как сырьё для анализа**:
формулировки перерабатываются в терминологии 4П, дословных заимствований нет, упоминаний источника
в пользовательской части нет.

---

## 1. Что в веб-версии уже сильнее исходной презентации

Повторный разбор подтвердил: бонусный блок корпоративного контура (сцены 17–19) закрывает целый пласт
управленческих идей, которых в PPTX не было вовсе.

| Идея материала | Где реализована |
|---|---|
| Маршрутизация запроса по уровню данных | `enterprise-gateway` — шлюз, четыре маршрута, учебный маршрутизатор |
| Локальные модели против внешних, поиск по внутренним документам | `enterprise-gateway` — `localItems`, RAG назван и объяснён |
| Теневой ИИ как реальная причина утечек | заметки `enterprise-why` |
| Начинать с задач и данных, а не с закупки инфраструктуры | `enterprise-path` — шаг 1 и 2, заметки |
| Пилот → помощник → контур | `enterprise-path` — три уровня |
| Связка контура с 4П | `enterprise-path` — блок `fourP` |
| Правило «значимые действия подтверждает человек» | `safe-agent`, `enterprise-gateway` |

Вывод: архитектурную часть переписывать не нужно. Обогащение касается блока «Перестроить» и точечных
формулировок.

## 2. Найденные пробелы

### П-1. Уровни делегирования не показывают цену автономности

`chat-assistant-agent` объясняет, **что** умеет каждый уровень, но не отвечает на вопрос руководителя
«чем я за это плачу». Из-за этого зал воспринимает три уровня как лестницу, по которой надо подниматься,
и тянется сразу к агенту. Материал даёт точный контртезис: это не эволюционная лестница, а разные
инструменты; главная ошибка — брать агента там, где хватает одного запроса.

### П-2. Выбор задачи подан как список равнозначных признаков

`pick-task` — восемь чипов одного веса. Ни один не запоминается, и главная управленческая мысль
отсутствует: **автоматизируют не профессию, а операцию**. «Внедрить ИИ в закупки» — это не задача;
«проверить комплектность заявки» — задача. Без этой оптики чек-лист прикладывают к слишком крупным
объектам, и пилот тонет.

### П-3. Нет процессного взгляда «сейчас → после»

Между «маршрутом зрелости» (абстрактные ступени) и «измеряйте до и после» (метрики) отсутствует
промежуточное звено: конкретный процесс из нескольких шагов, в котором ИИ появляется ровно на одном
шаге. Именно эта картинка превращает «перестроить» из лозунга в управленческое действие и показывает,
что четыре шага из пяти не трогают — что и делает пилот дешёвым.

### П-4. Метрики есть, рамки пилота нет

`measure` отвечает «что мерить», но не отвечает «сколько это длится, кто участвует, что считать
результатом и что делать, если не получилось». Право закрыть пилот по цифрам — сильный управленческий
подарок аудитории: оно снимает страх начать.

### П-5. Отсутствуют три точечные мысли

- **Расчёт и интерпретация — разные вещи.** Цифры приходят из учётных систем, ИИ помогает объяснить
  их и задать вопросы к ним. Пропуск этого правила — самый частый способ получить правдоподобный,
  но выдуманный показатель в отчёте.
- **Доля результатов, принятых без правок** — самая информативная метрика качества пилота, её нет
  среди метрик сцены.
- **Куда уходит освободившееся время.** Экономия, о которой не договорились заранее, растворяется,
  и эффект остаётся на бумаге.

### П-6. У корпоративного контура нет владельца

`enterprise-path` описывает шаги и уровни, но не говорит, кто это ведёт. Материал даёт простое
распределение: бизнес владеет повесткой, ИТ — инфраструктурой, юристы — правовой рамкой; без
названного владельца инициатива растворяется между отделами.

## 3. Решения по сценам

| Сцена | Решение | Что меняется | Анимация |
|---|---|---|---|
| 4 `chat-assistant-agent` | усилить | у каждого уровня — строка «чем платим» (внимание человека → порядок в материалах → доступы, журнал, подтверждения); ключевая фраза переписана в тезис о минимально достаточном уровне | без изменений в таймлайне: строка «чем платим» входит вместе со своим уровнем |
| 12 `pick-task` | заменить содержимое | «Не автоматизировать профессию — найти операцию»: три отраслевые пары «не X, а Y» (закупки, договоры, техслужба) + пять фильтров вместо восьми чипов + строка красных флагов | новая: пары входят слева, фильтры — последовательно, с подсветкой |
| **новая** `process` | добавить | «Процесс сегодня — и процесс после»: два ряда по пять шагов, подсвечен один шаг с ИИ, три вывода, тезис «сначала выпрямите процесс» | новая: ряд «сейчас» → стрелка → ряд «после» со вспышкой изменённого шага |
| 13 `measure` → `pilot` | заменить содержимое | «Первый пилот»: шесть параметров рамки + три исхода (масштабировать / доработать один раз / закрыть) + метрики строкой, включая долю результатов без правок | новая: параметры stagger, исходы — последовательно |
| 9 `checklist` | усилить | добавлен девятый пункт «расчёты — из систем, не из ИИ» | не требуется |
| 19 `enterprise-path` | усилить | добавлена строка о владельце повестки | не требуется |
| 20 `finale` | усилить | пять шагов → шесть: добавлены фиксация «до» и вопрос о допустимых данных | существующий stagger подхватывает шестой шаг |
| заметки ведущего | дополнить | проверенные цифры с источниками, прецедент ответственности за ответ бота, промпт-инъекции, оговорка про RAG, работа со страхами команды, признаки остановки пилота, распределение ответственности | — |

### Что сознательно не добавляем

- Расчёт экономии «на салфетке», матрица приоритизации, анкета для команды — это инструменты воркшопа,
  а не сцены лендинга; остаются в заметках.
- Отдельная сцена про роли (куратор, евангелисты) — увела бы вводный курс в организационное
  проектирование; сведено к одной строке в `enterprise-path` и заметкам.
- Перечни сценариев по подразделениям, классы инструментов, метрики RAG, no-code-платформы,
  дорожная карта на 12 месяцев — вне рамки курса.
- Сцены «карта применений» и «страхи» по-прежнему не переносятся из PPTX: их роль распределена
  по демонстрациям, отраслевым примерам новой сцены `pick-task` и заметкам.

## 4. Влияние на структуру и хронометраж

- Сцен: **20 → 21**. `sceneOrder` получает `process` между `pick-task` и `measure`.
- Pin-сцен по-прежнему **8**. Новая сцена намеренно сделана спокойной (без pin): блок «Перестроить»
  уже содержит один длинный pin (`ladder`, +230%), второй сделал бы блок вязким.
- Прирост скролла: около одного экрана. Прирост времени показа: ~2,5 минуты (блок «Перестроить»
  с 8 до 10–11 минут).
- Навигация по главам не меняется: `process` попадает в главу «Перестроить».
- `speakerNotes` — тип `Record<SceneId, string>`, поэтому новая сцена без заметок не соберётся.
  Это защита от рассинхронизации, а не формальность.

## 5. Проверки перед пушем

1. `npx tsc --noEmit` и `npm run lint` — типы и линт.
2. `npm run build` — production-сборка.
3. Ручная проверка скролла: все pin-сцены отпинниваются корректно, между сценами нет мёртвых зон,
   новая сцена не ломает `ScrollTrigger.refresh` соседей.
4. Режим ведущего `?presenter=1`: переход по сценам стрелками, счётчик 21, заметки новой сцены.
5. `prefers-reduced-motion` и мобильный профиль: контент полный, анимации выключены.
